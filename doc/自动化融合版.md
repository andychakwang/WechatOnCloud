# 自动化融合版

> 本文描述 `andy/automation-lab` 分支新增的自动化实验能力。
> 线上 NAS 当前仍建议保持旧版不变；本分支先用于构建、测试和小范围验证。

## 目标

把 WechatOnCloud 的云微信执行端，与本地 `wecom-ai-assistant` 已验证过的业务逻辑融合：

- AI 回复：规则优先，未命中时生成 AI 草稿；发送前必须人工确认。
- 消息导入：可读取实例剪贴板，或先模拟 Ctrl+C 再读取远程微信里的选中文本。
- 规则沉淀：把当前 AI 草稿一键保存为待审核/已审核关键词规则。
- 企微接入资料：导入企业微信自动化 Mac 版导出的 FAQ、话术、人群分组和运营素材。
- 素材资产台账：把 `imageKey/materialKey`、标题、类型、标签、本机路径或 URL 独立登记，云端负责审核和治理，Mac 端负责按 key 映射真实文件。
- 受众资产：把联系人、客户群、群聊、标签和来源沉淀成长期对象，可一键填入群发队列。
- 群发队列：白名单/群聊名单逐条推进，可自动搜索打开目标会话，再发送下一条。
- 朋友圈半自动：生成/保存/审核朋友圈草稿，可由 Mac Bridge 领取并准备到本机剪贴板或当前输入框，不自动点击发布。
- 自动化资产包：规则、资料、受众、素材、群发队列和朋友圈草稿可以导出/预览/导入，便于测试版、开发版和 NAS 间迁移。
- 自动化预检：在 Runner 领取前检查总开关、Mac 心跳、队列开关、规则完整性、素材 key 和本机路径。
- Bridge 自动规划回复：企微 Mac 工具推送消息时可带 `planReplies=true`，云端自动把规则命中或 AI 草稿保存成待审回复；默认不批准 AI 草稿。
- 风险拦截：投诉、退款、验证码、账号、法律等高风险内容直接阻断。
- 冷却与限流：限制每小时发送量和单会话冷却时间，实例发送、Bridge 自动回复和群发都计入限额。
- Bridge 运行回执：Mac Runner/RPA 包上报 run-report 后，云端可把明确的 sent/delivered/prepared/failed 回执反写到 AI 回复、群发和朋友圈队列。
- 审计记录：记录谁、何时、向哪个实例触发了发送、填入或队列变更动作。

## 安全默认值

这不是一个默认全自动群发器。第一版刻意保守：

- 自动化总开关默认关闭。
- 每条规则默认 `approved=false`。
- 真正发送必须传 `confirm=true`。
- 未审核规则不能发送。
- 风险命中 `block` 时不能发送。
- AI 草稿只生成文本，不自动发送。
- Bridge 自动规划会写入待审回复草稿；只有显式传 `approveRuleReplies=true` 且命中已审核关键词规则时，才会把规则回复批准给 Mac Runner 拉取，AI 草稿不会自动批准。
- Bridge 回复进入 `send` 模式前会再次检查风险词、每小时上限和单会话冷却；`pull-replies --mode send` 只返回当前可发送的回复。
- 企微接入资料默认需要审核后才会参与 AI 回复和朋友圈文案。
- 群发队列默认未审核，且每次只发送一个目标。
- 群发自动搜索只使用官方客户端 UI 快捷键，不读取微信数据库、不调用私有协议。
- 朋友圈草稿只复制或填入正文，Bridge 只回写 `prepared/published` 状态，不负责选择图片或点击发布。
- 资产包导入默认会把群发队列和朋友圈草稿重置为未审核草稿，避免导入后被 Mac Runner 立刻领取执行。
- 自动化预检只读当前配置和队列，不会触发领取、发送或发布。

## 新增持久化文件

自动化配置与审计记录独立保存：

```text
/data/automation.json
```

Compose 中已通过 `./data-panel:/data` 持久化，因此它会落到宿主的 `data-panel/automation.json`。

## 环境变量

AI 草稿使用 OpenAI-compatible Chat Completions：

```env
AUTOMATION_AI_API_KEY=
AUTOMATION_AI_BASE_URL=https://api.openai.com/v1
AUTOMATION_AI_MODEL=gpt-4o-mini
```

也兼容 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`。

企微 Mac 工具外部推送资料使用 Bridge token，默认关闭：

```env
AUTOMATION_BRIDGE_TOKEN=
```

填入至少 16 位随机 token 后，Mac 工具可以通过 Bridge API 把 FAQ、话术、联系人分组、素材台账和新消息事件推送到面板。token 只放在环境变量或 NAS Compose 配置里，不写入 GitHub。

## 测试端口部署

自动化版建议先和生产面板并行跑，不直接替换 `36080` 上的稳定服务。本分支提供独立 compose：

```bash
AUTOMATION_AI_API_KEY=你的模型Key \
./scripts/deploy-automation-test.sh
```

脚本默认使用：

- `WOC_IMAGE_PREFIX=ghcr.io/andychakwang`
- `WOC_VERSION=andy-automation-usable-r61-2026-07-05`
- `WOC_TEST_HTTP_PORT=36081`
- `PANEL_ALLOWED_HOSTS=nasbot.cloud`

也可以手动指定：

```bash
WOC_IMAGE_PREFIX=ghcr.io/andychakwang \
WOC_VERSION=andy-automation-usable-r61-2026-07-05 \
WOC_TEST_HTTP_PORT=36081 \
PANEL_ALLOWED_HOSTS=nasbot.cloud \
AUTOMATION_AI_API_KEY=你的模型Key \
AUTOMATION_AI_BASE_URL=https://api.openai.com/v1 \
AUTOMATION_AI_MODEL=gpt-4o-mini \
docker compose -f docker-compose.automation-test.yml up -d
```

隔离项：

- 测试面板容器名：`woc-panel-automation-test`
- 测试数据目录：`./data-panel-automation-test`
- 默认测试端口：`36081`
- 生产面板 `woc-panel`、`./data-panel` 和 `36080` 不受影响

飞牛 NAS 的 Docker 面板可以直接导入固定版 compose，见：

```text
fnos/woc-automation-test/docker-compose.yaml
```

详细步骤见 [飞牛 NAS 自动化测试部署](./飞牛NAS自动化测试部署.md)。

首次进入测试面板后：

1. 新建一个测试微信实例并扫码登录。
2. 在「自动化工作台」选择该实例，先跑「实例自检」。
3. 配置 AI Key 后，用「读取选中文本」验证 AI 回复链路。
4. 创建 1-2 个测试群/联系人队列，先用测试内容跑「发下一条」。
5. 朋友圈先用「复制」模式验证，再尝试「填入」模式。

自动化工作台顶部有运营总览、下一步队列和预检结果：总开关、已审核资料、AI 回复待办、群发待发送目标、朋友圈待准备草稿、Mac Bridge 在线 worker、出箱待办、阻断项和推荐处理顺序会统一显示。总览来自 `/api/admin/automation/overview`，下一步队列来自 `/api/admin/automation/action-queue`，预检来自 `/api/admin/automation/preflight`；三者都只读当前 JSON store，不会触发发送、领取或发布。下一步队列会按当前待办统计可交给 Mac/RPA 的回复、群发和朋友圈任务，并可一键生成对应目标的 RPA 运行包预览。

## API

所有自动化管理接口都要求管理员登录。

### 自动化预检

```http
GET /api/admin/automation/preflight
```

返回当前自动化链路的只读体检报告，前端工作台顶部会展示同一份数据。

```json
{
  "report": {
    "generatedAt": "2026-07-05T00:00:00.000Z",
    "level": "block",
    "summary": { "ok": 2, "warn": 1, "block": 1 },
    "checks": [
      {
        "id": "material_missing",
        "level": "block",
        "title": "素材引用不存在",
        "message": "1 个 imageKey/materialKey 找不到对应素材资产。",
        "refs": ["规则「欢迎语」: demo-poster"]
      }
    ]
  }
}
```

当前预检覆盖：

- 自动化总开关、AI 草稿、规则自动回复、群发和朋友圈开关。
- Mac Bridge worker 是否在线，以及 Runner 目标是否覆盖待办队列。
- 已审核规则是否有触发词和可执行回复步骤。
- `imageKey/materialKey` 是否存在、启用、审核、类型匹配，并配置了 Mac 可访问的 `localPath`。
- 群发和朋友圈内容是否会被当前风控规则拦截。
- 群发目标、朋友圈草稿和近期 Runner 是否有失败记录。

### 下一步队列

```http
GET /api/admin/automation/action-queue?limit=20
```

返回 SaaS 工作台用的只读待处理动作队列。它会把预检阻断、AI 回复、受控群发目标、朋友圈半自动草稿和最近 Runner 失败聚合成统一 `items`，并按 `block`、`high`、`normal`、`low` 排序。接口只生成推荐动作，不会领取 Bridge 任务，也不会粘贴、发送或发布。Web 工作台会用队列里的 `target` 统计回复/群发/朋友圈待办，并把“生成 RPA 包”快捷入口自动切到单一目标或全队列。

### 实例自动化自检

```http
POST /api/admin/instances/:id/automation/self-test
```

检查当前实例的自动化基础环境：`DISPLAY`、`xclip`、`xdotool`、活动窗口和剪贴板回环。建议在第一次跑 AI 回复、群发队列或朋友圈草稿前先点管理页里的「实例自检」。

### 运营总览

```http
GET /api/admin/automation/overview
```

返回自动化工作台顶部的只读汇总：资料/规则数量、Bridge 消息待办、Mac worker 在线数、群发队列状态、朋友圈草稿状态和最近审计事件。它只读取当前 store，不会领取 Bridge 任务，也不会执行发送。

### 读取配置

```http
GET /api/admin/automation/config
```

### 企微接入资料

导入企业微信自动化 Mac 版导出的资料：

```http
POST /api/admin/automation/knowledge/import
Content-Type: application/json

{
  "source": "wecom-mac",
  "category": "faq",
  "approveImported": false,
  "mode": "upsert",
  "items": [
    {
      "title": "价格咨询边界",
      "category": "policy",
      "tags": ["价格", "报价"],
      "triggers": ["多少钱", "费用", "报价"],
      "content": "价格问题先确认客户场景，不在 AI 回复里编造报价。",
      "targetNames": []
    },
    {
      "title": "测试群发白名单",
      "category": "contact-group",
      "targetNames": ["测试客户群", "张三"]
    }
  ]
}
```

也可以把 JSON、Markdown 或纯文本块放在 `rawText` 字段里，后端会按段落拆成资料。`mode=upsert` 会按 `source + title` 更新同名资料，避免重复导入。

更新审核/启用状态：

```http
PATCH /api/admin/automation/knowledge/:itemId
Content-Type: application/json

{ "approved": true, "enabled": true }
```

删除资料：

```http
DELETE /api/admin/automation/knowledge/:itemId
```

只有 `enabled=true` 且 `approved=true` 的资料会被送进 AI prompt；未审核资料只保存在工作台，不影响实际回复。

### 受众资产

导入企业微信自动化 Mac 版导出的联系人、客户群或群聊：

```http
POST /api/admin/automation/audience/import
Content-Type: application/json

{
  "source": "wecom-mac",
  "type": "group",
  "approveImported": false,
  "mode": "upsert",
  "contacts": [
    {
      "name": "测试客户群",
      "aliases": ["测试群"],
      "tags": ["白名单", "活动提醒"],
      "note": "只用于自动化 smoke 和小范围验证"
    }
  ]
}
```

也可以把一行一个联系人/群聊名放在 `rawText` 字段里。`mode=upsert` 会按 `source + name + type` 更新同名受众，避免重复导入。受众本身不会触发发送，只是长期资产；创建群发队列时仍会生成独立的受控队列，并继续走审核、限流和 Bridge 领取流程。

读取、更新、删除：

```http
GET /api/admin/automation/audience?limit=200&query=&tag=
PATCH /api/admin/automation/audience/:contactId
DELETE /api/admin/automation/audience/:contactId
```

### 素材资产台账

素材资产用于把云端稳定 key 和 Mac 本机真实文件解耦。云端只保存元数据，不上传图片、视频或文件二进制；Mac runner 在执行 `replySteps` 或朋友圈任务时，仍通过 `WECOM_MATERIAL_MAP` / `WECOM_MATERIAL_MAP_FILE` 把 key 解析为本机路径。

导入示例：

```http
POST /api/admin/automation/materials/import
Content-Type: application/json

{
  "source": "wecom-mac",
  "kind": "image",
  "approveImported": false,
  "mode": "upsert",
  "assets": [
    {
      "key": "demo-poster",
      "title": "Demo Poster",
      "localPath": "/Users/andy/Pictures/material.png",
      "tags": ["海报", "朋友圈"],
      "description": "用于回复序列和朋友圈草稿的本机素材"
    }
  ]
}
```

也可以用一行一个素材的文本导入：

```text
demo-poster | Demo Poster | /Users/andy/Pictures/material.png | 海报,朋友圈 | 用于 smoke 验证
```

读取、更新、删除：

```http
GET /api/admin/automation/materials?limit=200&query=&tag=
PATCH /api/admin/automation/materials/:assetId
DELETE /api/admin/automation/materials/:assetId
```

素材台账里的 `approved/enabled` 只代表云端资产可用性；真正执行前，Mac 端仍会检查 key 是否映射到存在的本机文件。未映射或路径不存在时，`dry-run` 会显示缺失项，`prepare/send` 会失败回写而不会继续发送。

### 自动化资产包

资产包用于把一套自动化配置从开发版迁移到测试版，或在升级前做结构化备份。Web 工作台可以直接下载 JSON，也可以粘贴 JSON 先 dry-run 预览，再确认导入。

导出：

```http
GET /api/admin/automation/bundle
```

返回结构包含：

```json
{
  "schema": "wechat-on-cloud.automation-bundle",
  "version": 1,
  "summary": {
    "rules": 1,
    "knowledgeItems": 3,
    "audienceContacts": 20,
    "materialAssets": 5,
    "massSendJobs": 2,
    "momentDrafts": 4,
    "bridgeEvents": 0
  },
  "config": {},
  "audienceContacts": [],
  "materialAssets": [],
  "massSendJobs": [],
  "momentDrafts": []
}
```

预览导入：

```http
POST /api/admin/automation/bundle/import
Content-Type: application/json

{
  "dryRun": true,
  "mode": "upsert",
  "includeConfig": true,
  "keepOperationalState": false,
  "bundle": { "schema": "wechat-on-cloud.automation-bundle" }
}
```

确认导入时把 `dryRun` 改为 `false`。`mode=upsert` 会按规则名、资料 `source+title`、受众 `source+type+name`、素材 `source+key`、队列标题和草稿标题更新；`mode=append` 会全部追加。默认 `keepOperationalState=false`，因此导入的群发队列和朋友圈草稿会变成未审核草稿，不会立刻进入 Bridge 出箱。

### Mac Bridge 推送

测试面板设置 `AUTOMATION_BRIDGE_TOKEN` 后，企业微信自动化 Mac 版可以不登录 Web 管理页，直接推送资料：

```http
POST /api/automation/bridge/wecom/import
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
Content-Type: application/json

{
  "source": "wecom-mac",
  "category": "faq",
  "mode": "upsert",
  "approveImported": false,
  "items": [
    {
      "title": "价格咨询边界",
      "tags": ["价格"],
      "triggers": ["多少钱", "报价"],
      "content": "价格问题先确认客户场景，不在 AI 回复里编造报价。"
    }
  ]
}
```

也可以用 `X-Automation-Token: <token>` 请求头。Bridge 只负责导入资料，不执行发送、群发或朋友圈发布动作；导入后的资料仍需要管理员审核后才会影响 AI 回复。

Mac 工具也可以同步联系人、客户群或群聊到受众资产池：

```http
    { "name": "测试客户群", "tags": ["白名单"] }

```

Mac 工具也可以同步素材资产台账：

```http
POST /api/automation/bridge/wecom/materials
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
Content-Type: application/json

{
```

如果要把云控队列交给现有“企业微信自动化 Mac 版”项目处理，而不是立刻让 Bridge runner 执行，可以先导出标准 RPA 运行包：

```bash
node scripts/wecom-bridge-client.mjs export-rpa-package \
  --target all \
  --limit 50 \
  --format jsonl \
  --output-dir ~/.config/wechat-on-cloud/rpa-packages
```

`export-rpa-package` 是只读命令：它只拉取已批准且待处理的 AI 回复、受控群发目标和朋友圈草稿，不会领取任务、不会粘贴、不会发送。输出包使用 `woc.wecom.rpa.package.v1` / `woc.wecom.rpa.task.v1` schema；每条任务都会带 `target`、`operation`、`expectedName`、`text`、`textChars`、`requiresOperatorReview`，并按类型补充：

- `reply.prepare`：`conversationName`、`senderName`、`inboundText`、`steps`、`imageStepCount`。
- `mass.prepare`：`recipientName`、`jobId`、`itemId`、`jobTitle`。
- `moment.prepare`：`draftId`、`title`、`imageNotes`、`materials`。

Mac 端也可以直接消费这个 JSON/JSONL 包，把任务分发给现有 handler：

```bash
node scripts/wecom-bridge-client.mjs run-rpa-package \
  ~/.config/wechat-on-cloud/rpa-packages/latest.jsonl \
  --target all \
  --mode dry-run \
  --handler-reply ./scripts/wecom-mac-reply-handler.sh \
  --handler-mass ./scripts/wecom-mac-mass-handler.sh \
  --handler-moment ./scripts/wecom-mac-moment-handler.sh
```

`run-rpa-package` 默认只做 `dry-run`，会读取包、校验任务结构，并调用三个 handler 的 dry-run 逻辑，不会领取任务、不会回写成功状态，也不会触碰企业微信发送动作。改成 `--mode prepare` 时，回复/群发会准备输入框，朋友圈会复制草稿或按 `WECOM_MOMENT_PASTE_MODE` 进入半自动准备；改成 `--mode send` 时，只允许回复和群发在本机设置 `WECOM_ALLOW_SEND=1` 后真实发送，朋友圈仍会降级为半自动 `prepare`。需要让包执行结果回写云端时再加：

```bash
# 成功后回写 delivered/sent/prepared；失败时也写 failed，并生成一次运行报告
node scripts/wecom-bridge-client.mjs run-rpa-package latest.jsonl \
  --mode prepare \
  --ack \
  --report-failure \
  --report-run
```

这样旧的“企业微信自动化 Mac 版”既可以自己消费包完成窗口定位、输入框校验、素材解析和人工确认，也可以逐步复用本仓库的 handler 与回写能力。中间的 RPA 包是可审计边界：云端负责审核/队列/AI 草稿，本机负责真实企业微信 RPA。

如果不想先落盘再运行，Mac 端可以直接从面板拉取一份标准 RPA 包并执行：

```bash
node scripts/wecom-bridge-client.mjs run-cloud-rpa-package \
  --target all \
  --limit 50 \
  --mode dry-run \
  --save-package-dir ~/.config/wechat-on-cloud/rpa-packages
```

`run-cloud-rpa-package` 内部复用同一套 `woc.wecom.rpa.package.v1` 包格式：先用 Bridge token 拉取待处理回复、群发目标和朋友圈草稿，再把包里的任务分发给 reply/mass/moment handler。它默认仍是安全的 `dry-run`，不会领取任务；`--mode prepare/send` 的执行语义和 `run-rpa-package` 一致，`--save-package-dir` 会额外保留本轮拉到的 JSONL 包，方便把这份包交给现有“企业微信自动化 Mac 版”项目排查或二次处理。

Runner 也支持走这个包边界，便于逐步替换旧项目的任务入口：

```bash
WECOM_USE_RPA_PACKAGE=1 \
WECOM_RUNNER_MODE=dry-run \
WECOM_RUNNER_TARGET=all \
scripts/wecom-bridge-runner.sh run-once
```

常驻运行时可在 `~/.config/wechat-on-cloud/wecom-bridge.env` 里加入 `WECOM_USE_RPA_PACKAGE=1` 和 `WECOM_RPA_PACKAGE_SAVE_DIR=$HOME/.config/wechat-on-cloud/rpa-packages`。这个模式会先回传 Mac worker 心跳，再通过统一 RPA 包处理队列；真实 `send` 仍需要本机显式设置 `WECOM_ALLOW_SEND=1`，朋友圈仍只进入半自动准备，不会自动点击发布。

Web 管理页的「Mac Bridge / RPA 运行包」也可以生成同一份包，适合 SaaS 面板里人工下载、交给 Mac 项目执行，或先检查待办数量。对应只读接口：

```http
GET /api/admin/automation/rpa-package?target=all&limit=50&format=json
GET /api/admin/automation/rpa-package?target=all&limit=50&format=jsonl&download=1
```

`target` 支持 `replies`、`mass`、`moments`、`all`；`limit` 是每类任务的上限；`includeSource=1` 会把源任务一起放进包里用于排障。这个 Web 导出接口和 CLI 导出一样不会 claim、不会回写、不会发送。

管理员可以在 Web 管理页维护 Mac Runner 的云端策略，也可以直接调用接口：

```http
GET /api/admin/automation/runner-policy
PUT /api/admin/automation/runner-policy
Content-Type: application/json

{
  "runnerEngine": "bridge",
  "mode": "dry-run",
  "target": "all",
  "limit": 5,
  "claimTtlSeconds": 300,
  "heartbeatIntervalSeconds": 60,
  "momentPasteMode": "clipboard-only",
  "allowSend": false,
  "requireTargetMatch": true,
  "requireHandlerVerification": true
}
```

Bridge worker 可在本机定时任务启动时拉取这份策略：

```http
GET /api/automation/bridge/wecom/runner-policy?workerId=mac-mini-01
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
```

返回体包含 `policy` 和可直接映射成本机环境变量的 `env`。`runnerEngine=bridge` 是默认队列执行方式；`runnerEngine=rpa-package` 会下发 `WECOM_RUNNER_ENGINE=rpa-package` 和 `WECOM_USE_RPA_PACKAGE=1`，Mac runner 每轮会先拉取标准 RPA 包，再按包内任务分发到 reply/mass/moment handler。这个模式适合让现有“企业微信自动化 Mac 版”项目只对接统一包格式，而不直接理解云端多个队列 API。如果云端策略选择 `send`，仍需要本机显式设置 `WECOM_ACCEPT_REMOTE_SEND=1` 或 `WECOM_ALLOW_SEND=1`，否则 runner 会自动降级为 `prepare`。`requireTargetMatch=true` 会下发 `WECOM_REQUIRE_TARGET_MATCH=1`，让回复和群发 handler 在粘贴/发送前硬校验企业微信窗口标题。`requireHandlerVerification=true` 会下发 `WECOM_REQUIRE_HANDLER_VERIFICATION=1`，Bridge client 只有在 handler 回传正向 `verification` 后才会把回复、群发或朋友圈任务标记为成功；校验缺失或失败会进入 failed 并写入运行报告。`WECOM_BRIDGE_CAPABILITIES` 可显式覆盖 worker 心跳和领取回写能力清单；云端会按已声明能力拦截不匹配的回复、群发或朋友圈任务领取/成功回写。朋友圈目标不支持无人值守 `send`；保存策略时会规范为半自动 `prepare`。

管理员可用 `GET /api/admin/automation/bridge-runs?limit=50` 查看最近运行报告；报告会保留最近 300 条，用于 SaaS 运维看板和多 worker 排障。

如果 Mac Runner 掉线、中断或任务失败，管理员可以在 Web 管理页预览并恢复 Bridge 出箱，也可以直接调用接口：

```http
POST /api/admin/automation/bridge-recovery
Content-Type: application/json

{
  "releaseClaims": "expired",
  "retryFailed": true,
  "workerId": "mac-mini-01",
  "failureReason": "window not ready",
  "minFailedAgeSeconds": 300,
  "maxRetryAttempts": 3,
  "limit": 100,
  "cursor": "reply|retry-failed|evt_122"
}
```

默认只释放已超时领取，并把失败的 AI 回复、群发目标和朋友圈草稿重新放回待处理队列；不会直接发送内容。管理页支持先 `dryRun` 预览、按回复/群发/朋友圈限定范围、按 worker、失败原因、失败冷却、重试次数上限和 cursor 分批恢复，再执行恢复。带 `workerId` 时，只释放该 worker 的领取，只重试记录为该 worker 失败的任务；历史失败项如果没有失败归属，会在 worker 过滤下跳过。带 `failureReason` 时，只重试错误文本包含该内容的失败项；带 `minFailedAgeSeconds` 时，刚失败且未过冷却时间的任务会暂缓重试；带 `maxRetryAttempts` 时，已达到该恢复次数的失败项会跳过，`0` 表示不限。领取释放不受失败原因、失败冷却和重试上限影响。返回体会按 `replies`、`mass`、`moments` 统计释放和重试数量，并给出本轮变更明细：

```json
{
  "result": {
    "dryRun": false,
    "releaseClaims": "expired",
    "retryFailed": true,
    "workerId": "mac-mini-01",
    "failureReason": "window not ready",
    "minFailedAgeSeconds": 300,
    "maxRetryAttempts": 3,
    "limit": 100,
    "hasMore": true,
    "nextCursor": "reply|retry-failed|evt_123",
    "replies": { "releasedClaims": 0, "retriedFailed": 1 },
    "mass": { "releasedClaims": 0, "retriedFailed": 1, "resumedJobs": 1 },
    "moments": { "releasedClaims": 0, "retriedFailed": 1 },
    "totalChanged": 3,
    "changes": [
      { "target": "reply", "id": "evt_123", "action": "retry-failed", "reason": "failed_retry", "workerId": "mac-mini-01", "error": "window not ready", "failedAt": "2026-07-05T06:30:00.000Z", "retryCount": 1, "nextRetryCount": 2, "cursor": "reply|retry-failed|evt_123" }
    ]
  }
}
```

可选参数：

- `dryRun: true`：只预览，不落库。
- `releaseClaims: "all"`：强制释放全部未交付领取，用于明确要接管某台 worker 的任务。
- `workerId: "mac-mini-01"`：按 worker 精准恢复；领取态匹配 `replyClaimedBy` / `bridgeClaimedBy`，失败态匹配 `replyFailedBy` / `bridgeFailedBy`。
- `failureReason` / `errorContains`：按失败原因文本筛选重试项；只影响失败重试，不影响领取释放。
- `minFailedAgeSeconds` / `failedCooldownSeconds`：失败冷却时间；失败时间未达到该秒数的重试项会跳过，默认 0，最大 7 天。老数据没有失败时间时，如果启用冷却会跳过。
- `maxRetryAttempts` / `maxRetries`：失败恢复次数上限；每次真正把失败项恢复为待处理时加 1，达到上限后跳过，默认 0 表示不限。
- `includeReplies` / `includeMass` / `includeMoments`：按类型限定恢复范围。
- `limit`：限制本轮最多处理的变更项，默认 500，最大 2000。
- `cursor` / `afterCursor`：从上次返回的游标之后继续扫描；当 `hasMore` 为 true 时，用 `nextCursor` 拉取下一批。

管理员在收件箱里保存并批准回复草稿后，Mac 工具可以拉取待执行回复：

```http
GET /api/automation/bridge/wecom/replies?limit=50
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
```

返回的是已批准、未交付、未归档的事件，包含 `replyDraft`、可选 `replySteps`、会话名和原始消息。`replyDraft` 是单段兼容文本；`replySteps` 用于云端顺序回复，当前支持：

```json
[
  { "type": "text", "text": "第一段回复", "sendEnter": true },
  { "type": "wait", "seconds": 3 },
  { "type": "image", "imagePath": "/Users/andy/Pictures/material.png", "sendEnter": true },

  { "type": "wait", "seconds": 2 },
  { "type": "text", "text": "第二段回复", "sendEnter": true }
]
```

这对应企业微信自动化 Mac 版里的 `KeywordReplyStep`：`contentType=text` 映射为 `text` 步骤，`contentType=image` 映射为 `image` 步骤，`delayBeforeSendingSeconds` 映射为前置 `wait` 步骤。图片可以直接传 Mac runner 本机 `imagePath`，也可以只传云端稳定的 `imageKey` / `materialKey`；后者由 Mac runner 用本机素材映射解析成真实路径，不上传二进制到云端。`prepare/send` 时路径不存在或 key 未映射会失败回写，`dry-run` 会显示 `imageStepCount`、缺失路径和缺失 key。Mac 工具执行前仍应在本机界面做一次人工确认或停在发送前确认。

```http
{
  "deliveryStatus": "claimed",
  "workerId": "mac-mini-01",
  "claimTtlSeconds": 300
}
```

领取后的回复默认不会再出现在 `GET /replies` 待处理列表里；如果 Mac 工具没有回写成功/失败，领取状态默认 300 秒后过期，届时该回复会重新出现在待处理列表中。Mac 工具处理失败时，可以标记失败并记录原因，方便 Web 面板查看和下次重试：

```http
PATCH /api/automation/bridge/wecom/replies/:eventId
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
Content-Type: application/json

{
  "deliveryStatus": "failed",
  "workerId": "mac-mini-01",
  "error": "企业微信窗口未找到"
}
```

如果只是本机取消处理、窗口没准备好，想立即放回待处理列表，可以释放领取：

```http
PATCH /api/automation/bridge/wecom/replies/:eventId
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
Content-Type: application/json

{
  "deliveryStatus": "released",
  "workerId": "mac-mini-01"
}
```

Mac 工具处理成功后，可以标记已交付：

```http
PATCH /api/automation/bridge/wecom/replies/:eventId
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
Content-Type: application/json

{
  "deliveryStatus": "delivered",
  "workerId": "mac-mini-01"
}
```

为了兼容早期客户端，空 JSON `{}` 仍等价于 `delivered`。

这只会记录 `replyDeliveredAt`，不会由云端直接发送消息。

管理员审核并启动群发队列后，Mac 工具也可以拉取受控群发任务：

```http
GET /api/automation/bridge/wecom/mass-tasks?limit=50
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
```

返回的是已开启自动化总开关、已开启群发开关、已审核且状态为 `queued/running` 的队列任务。每个队列同一时间只暴露第一个 `pending` 目标，保证顺序推进；被有效领取的目标不会再出现在待处理列表中。

```http
PATCH /api/automation/bridge/wecom/mass-tasks/:taskId
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
Content-Type: application/json

{
  "deliveryStatus": "claimed",
  "workerId": "mac-mini-01",
  "claimTtlSeconds": 300
}
```

`deliveryStatus` 可取：

- `claimed`：领取任务，默认 300 秒后超时释放。
- `released`：窗口未准备好时释放领取，立即回到待处理列表。
- `failed`：标记当前目标失败，并暂停队列，Web 管理页可重置或跳过。
- `sent` / `delivered`：标记当前目标已发送，队列继续推进或完成。

这只会更新队列状态；真正打开企业微信、搜索目标、粘贴或发送消息仍发生在 Mac 本机。

管理员审核朋友圈草稿并置为 `ready` 后，Mac 工具可以拉取半自动朋友圈任务：

```http
GET /api/automation/bridge/wecom/moment-tasks?limit=50
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
```

返回的是已开启自动化总开关、已开启朋友圈开关、已审核且状态为 `ready` 的草稿。被有效领取的草稿不会再出现在待处理列表中。

```http
PATCH /api/automation/bridge/wecom/moment-tasks/:taskId
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
Content-Type: application/json

{
  "deliveryStatus": "claimed",
  "workerId": "mac-mini-01",
  "claimTtlSeconds": 300
}
```

`deliveryStatus` 可取：

- `claimed`：领取草稿，默认 300 秒后超时释放。
- `released`：窗口未准备好时释放领取，立即回到待处理列表。
- `failed`：标记准备失败，草稿退回未审核 `draft`，避免反复重试。
- `prepared`：Mac 端已把文案准备到剪贴板或当前输入框，Web 状态变为 `prepared`。
- `published`：人工确认已经发布后回写状态；Bridge 本身不会点击发布。

这只会更新草稿状态；真正打开企业微信、进入朋友圈、粘贴正文和发布确认仍发生在 Mac 本机。

如果 Mac 项目已经有本地发送脚本，可以用 `run-approved` 串起来：

```bash
node scripts/wecom-bridge-client.mjs run-approved \
  --handler './send-to-wecom.sh' \
  --claim \
  --mark-delivered \
  --report-failure
```

`run-approved` 会把单条回复 JSON 写入 handler 的 stdin，并设置 `WECOM_BRIDGE_REPLY_ID`、`WECOM_BRIDGE_CONVERSATION_NAME`、`WECOM_BRIDGE_SENDER_NAME`、`WECOM_BRIDGE_REPLY_DRAFT`、`WECOM_BRIDGE_REPLY_STEPS`、`WECOM_BRIDGE_REPLY_STEP_COUNT`、`WECOM_BRIDGE_REPLY_IMAGE_STEP_COUNT` 环境变量。仓库自带的 Mac handler 在 prepare/send 成功后会默认读取企业微信前台窗口标题，并把 `verification` 快照写到 stdout，Bridge client 会随运行报告回传到云端；如需临时关闭，设置 `WECOM_VERIFY_TARGET=0`。启用 `WECOM_REQUIRE_TARGET_MATCH=1` 后，handler 会在搜索会话后、粘贴/发送前读取窗口标题；如果未命中目标会话，会以非 0 退出并回传失败校验快照，不会继续写入输入框。启用 `WECOM_REQUIRE_HANDLER_VERIFICATION=1` 后，即使 handler 退出码为 `0`，只要没有回传 `verified/conversationMatched/inputReady` 等正向信号，Bridge client 也不会执行 `--mark-delivered`，而是把任务标记为 failed。只有 handler 退出码为 `0`、交付校验通过，并且显式传了 `--mark-delivered`，客户端才会回写已交付。这样 Mac 侧仍可以停在发送前确认或做本机风控。

`--claim-ttl-seconds` 可控制领取超时时间，默认 300 秒。超时后回复会再次被 `pull-replies`/`run-approved` 拉到；未超时前，其他 worker 不能抢占同一条回复。

```bash
scripts/wecom-bridge-runner.sh run-once
```

`doctor` 只做接入体检，不会领取回复、群发或朋友圈任务，也不会触碰企业微信输入框。它会检查 `node`、`osascript`、LaunchAgent 环境、runner/handler 文件、配置文件权限、素材映射文件、Bridge token 和远端 Runner 策略；默认还会用 AppleScript 读取企业微信进程和窗口标题，用于提前发现 macOS 自动化/辅助功能权限问题。设置 `WECOM_DOCTOR_REMOTE=0` 可跳过远端策略鉴权，设置 `WECOM_DOCTOR_APP=0` 可跳过真实企业微信窗口检查。设置 `WECOM_DOCTOR_REPORT=1` 后，体检结果会以 `target=doctor` 回传到云端 `run-report`，Web 管理页「最近运行」会显示“接入体检”和每项 OK/WARN/FAIL 明细。

runner 每次运行都会先上报一次 `heartbeat`，即使没有待处理回复、群发任务或朋友圈任务，Web 管理页也能看到 Mac 端最近是否在线；runner 调用 `run-approved`、`run-mass`、`run-moments` 时会带 `--report-run` 自动回写本轮运行报告。prepare 模式会 `claim` 当前任务，因此不会重复出现在待处理列表里；人工确认发送后，应再执行 `mark-delivered <eventId>` 或 `mark-mass-sent <taskId>`；人工确认朋友圈已经发布后，执行 `mark-moment-published <taskId>`。`WECOM_RUNNER_TARGET=all` 会按 replies → mass → moments 顺序运行；真实无人值守发送只建议在小号/测试群充分验证后启用 `send`；朋友圈 target 当前不支持 runner 的 `send` 模式，all+send 也会跳过朋友圈发布。启用 `WECOM_USE_REMOTE_POLICY=1` 后，本机每次运行会先向面板拉取云端 Runner 策略；如果云端把 `runnerEngine` 设为 `rpa-package`，本机会自动切到 `run-cloud-rpa-package`，统一通过 RPA 包执行 AI 回复、群发和朋友圈半自动任务；如果云端允许 `send`，本机仍需设置 `WECOM_ACCEPT_REMOTE_SEND=1` 才会接受远程真实发送授权，否则自动降级为 `prepare`；如果云端开启 `requireTargetMatch`，本机会自动设置 `WECOM_REQUIRE_TARGET_MATCH=1`；如果开启 `requireHandlerVerification`，本机会自动设置 `WECOM_REQUIRE_HANDLER_VERIFICATION=1`，要求 handler 回传正向校验后才回写成功状态。回复任务如果带 `replySteps`，runner 会把步骤原样交给 Mac handler；dry-run 输出会显示 `stepCount`、`imageStepCount`、缺失图片路径和未映射素材 key，便于先检查队列而不碰企业微信窗口。prepare/send 输出会带窗口标题校验快照，Web 管理页最近运行报告可直接看到“校验通过/失败”和命中的窗口名；本机设置 `WECOM_REQUIRE_TARGET_MATCH=1` 时，回复和群发会在粘贴前硬拦截目标不匹配。

### 群发队列

创建队列：

```http
POST /api/admin/automation/mass-jobs
Content-Type: application/json

{
  "title": "6 月活动提醒",
  "message": "这是一条经过确认的群发内容",
  "recipients": ["客户群 A", "张三"],
  "options": {
    "perSendDelaySeconds": 10,
    "requireOperatorConfirmRecipient": true,
    "openConversationBeforeSend": true,
    "searchShortcut": "ctrl+f",
    "searchResultDelaySeconds": 2,
    "postOpenDelaySeconds": 1
  }
}
```

也可以从已导入的受众资产直接生成队列；默认只选入已启用、已审核的受众，生成后仍是独立的未审核队列，不会绕过审核、限流和 Bridge 领取机制：

```http
POST /api/admin/automation/mass-jobs/from-audience
Content-Type: application/json

{
  "title": "活动提醒 - 白名单客户群",
  "message": "这是一条经过确认的群发内容",
  "audienceFilter": {
    "tag": "活动提醒",
    "type": "group",
    "limit": 100
  },
  "options": {
    "perSendDelaySeconds": 10,
    "requireOperatorConfirmRecipient": true,
    "openConversationBeforeSend": true
  }
}
```

审核/暂停/取消队列：

```http
PATCH /api/admin/automation/mass-jobs/:jobId
Content-Type: application/json

{ "approved": true, "status": "queued" }
```

发送下一条：

```http
POST /api/admin/instances/:id/automation/mass-jobs/:jobId/send-next
Content-Type: application/json

{
  "confirm": true,
  "operatorConfirmedRecipient": true,
  "openConversationBeforeSend": true
}
```

注意：

- `openConversationBeforeSend=true` 时，面板会尝试用搜索快捷键打开目标会话，再粘贴发送内容。
- 如果某个微信版本快捷键不一致，可把队列改成 `openConversationBeforeSend=false`，回到“人工打开当前会话后发送”的受控模式。
- 无论哪种模式，每次发送仍要求 `confirm=true` 和 `operatorConfirmedRecipient=true`。
- 如果发送失败，队列会自动暂停，当前目标标记为 `failed`，管理页可把目标重置为 `pending` 后重试，也可以跳过继续跑后续目标。

更新单个队列目标状态：

```http
PATCH /api/admin/automation/mass-jobs/:jobId/items/:itemId
Content-Type: application/json

{ "status": "skipped", "reason": "本次不发送" }
```

## 和 wecom-ai-assistant 的融合关系

已融合的部分：

- `ReplyPipeline` 思路：先关键词规则，再知识库/AI，再人工处理。
- 企微自动化 Mac 版资料接入：FAQ、话术、边界、人群分组和朋友圈素材可以导入为结构化资料。
- 受众资产池：联系人、客户群、群聊、标签和来源可长期沉淀，并一键填入群发目标或按筛选直接生成受控群发队列。
- 素材资产台账：`imageKey/materialKey` 可在云端登记、审核、启停和删除，Mac 端按本机映射解析真实文件。
- Bridge 素材映射：Mac Runner 可用 token 拉取已审核素材，生成 `WECOM_MATERIAL_MAP_FILE`，减少手工维护 key/path JSON。
- 自动化资产包：规则、接入资料、受众、素材、群发队列和朋友圈草稿可导出、dry-run 预览并导入到另一套测试面板。
- Mac Bridge：企微 Mac 工具可用 token 把资料推送到云端面板，不必手工复制粘贴。
- Bridge 消息收件箱：企微 Mac 工具可把新消息推到面板，可由管理员一键生成并保存回复草稿，也可在推送时用 `--plan-replies` 自动生成待审草稿。
- Bridge 回复出箱：管理员批准后的回复草稿或顺序回复 `replySteps` 可供 Mac 工具拉取执行，云端仍不直接发送。
- Bridge 朋友圈出箱：管理员审核后的朋友圈草稿可供 Mac 工具领取并准备，人工发布后回写状态。
- Bridge 运行明细：Mac Runner 每轮可回写结构化 `items`，管理页最近运行报告能看到具体任务、动作和失败原因。
- Bridge 目标校验快照：Mac/RPA handler 可把目标会话匹配、窗口标题、OCR 文本、输入框就绪状态随运行报告回传，云端管理页可见。
- Bridge 出箱恢复：管理员可在管理页预览、限定队列范围、worker、失败原因、失败冷却和重试次数上限，分批释放超时领取，并把失败的回复、群发目标和朋友圈草稿重新放回待处理队列。
- Mac Runner 接入体检：本机可用 `scripts/wecom-bridge-runner.sh doctor` 检查脚本、配置权限、Bridge token、云端策略、素材映射和企业微信窗口权限；设置 `WECOM_DOCTOR_REPORT=1` 后会把体检结果回传到云端最近运行报告，上线前先排除环境问题。
- AI 回复和朋友圈文案会自动引用已审核接入资料；人群分组可在管理页填入群发目标。
- `RiskClassifier` 思路：阻断高风险词，普通词放行，部分词进入复核。
- `KeywordReplyStep` 思路：多段文本、图片素材路径与延迟步骤已经可由云端保存、Bridge 拉取，并由 Mac handler 在 prepare/send 模式按序处理。
- `AutomaticReplyPolicy` 思路：已审核规则、冷却时间、每小时上限。
- 自动化预检：在 Mac Runner 领取前检查开关、心跳、目标队列、规则、素材和风控阻断。
- 审计和人工确认优先的产品边界。
- 管理页工作台：AI 回复、群发队列、朋友圈草稿和最近审计记录集中在一个入口。
- Docker 执行器：会话搜索打开、实例剪贴板读写、自动化环境自检。
- 群发队列恢复能力：失败自动暂停，目标可跳过、重置或标记失败。

尚未融合的部分：

- Mac 版工具已经可以通过 Bridge 领取 AI 回复、群发任务和朋友圈任务，并由本机 handler 搜索会话、准备文案、粘贴或发送；云端已支持接收目标会话/OCR/窗口校验快照，回复和群发 handler 已支持 `WECOM_REQUIRE_TARGET_MATCH=1` 的窗口标题硬门禁，Bridge client 也支持 `WECOM_REQUIRE_HANDLER_VERIFICATION=1` 的交付成功门禁，但真实 OCR 与视觉识别 handler 仍需接入。
- 读取微信聊天消息：当前版本还没有可靠 OCR/窗口识别。
- 联系人/群匹配校验：云端已有回传和展示通道，当前还缺 Mac 端 OCR/视觉识别来稳定反查“是否确实打开了目标会话”。
- 朋友圈发布状态机：当前 Bridge 已支持半自动领取、准备和状态回写，未实现自动打开入口、选图和点击发布的 RPA 流程。

## 下一步

1. 增加实例内感知：截图、OCR、输入框定位和视觉摘要。
2. 增强联系人/群匹配校验：当前已有窗口标题硬门禁，下一步接入 OCR/视觉识别反查“确实打开了目标会话”。
3. 增强朋友圈 RPA：自动打开朋友圈入口、进入发布框、选图、填文案、停在发布确认前。
4. 增加按队列策略恢复；群发 Bridge 当前按单队列顺序领取。
5. 小范围测试稳定后，再考虑构建自定义镜像并部署到 NAS 的单独测试端口。
