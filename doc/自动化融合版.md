# 自动化融合版

> 本文描述 `andy/automation-lab` 分支新增的自动化实验能力。
> 线上 NAS 当前仍建议保持旧版不变；本分支先用于构建、测试和小范围验证。

## 目标

把 WechatOnCloud 的云微信执行端，与本地 `wecom-ai-assistant` 已验证过的业务逻辑融合：

- 关键词规则：命中触发词后发送多段话术。
- 风险拦截：投诉、退款、验证码、账号、法律等高风险内容直接阻断。
- 冷却与限流：限制每小时发送量和单会话冷却时间。
- AI 草稿：接 OpenAI-compatible 模型生成一条回复草稿。
- 审计记录：记录谁、何时、向哪个实例触发了发送动作。

## 安全默认值

这不是一个默认全自动群发器。第一版刻意保守：

- 自动化总开关默认关闭。
- 每条规则默认 `approved=false`。
- 真正发送必须传 `confirm=true`。
- 未审核规则不能发送。
- 风险命中 `block` 时不能发送。
- AI 草稿只生成文本，不自动发送。

## 新增持久化文件

自动化配置与审计记录独立保存：

```text
/data/automation.json
```

Compose 中已通过 `./data-panel:/data` 持久化，因此它会落到宿主的 `data-panel/automation.json`。

## 环境变量

AI 草稿使用 OpenAI-compatible Chat Completions：

```env
AUTOMATION_AI_API_KEY=
AUTOMATION_AI_BASE_URL=https://api.openai.com/v1
AUTOMATION_AI_MODEL=gpt-4o-mini
```

也兼容 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`。

## API

所有自动化管理接口都要求管理员登录。

### 读取配置

```http
GET /api/admin/automation/config
```

### 保存配置

```http
PUT /api/admin/automation/config
Content-Type: application/json

{
  "settings": {
    "enabled": true,
    "maximumAutomaticSendsPerHour": 20,
    "perConversationCooldownMinutes": 10,
    "requireConfirmForSend": true
  },
  "persona": "你的账号人设和回复风格",
  "knowledgeNotes": "业务资料、报价边界、禁答规则",
  "rules": [
    {
      "id": "welcome-001",
      "name": "咨询欢迎语",
      "enabled": true,
      "approved": true,
      "priority": 10,
      "triggers": ["怎么了解", "咨询", "价格"],
      "responseSteps": [
        { "type": "text", "text": "你好，我先把资料发你，你可以先看一下。", "sendEnter": true },
        { "type": "wait", "seconds": 2 },
        { "type": "text", "text": "如果你方便，也可以直接说下你的需求，我帮你匹配。", "sendEnter": true }
      ],
      "createdAt": "2026-06-17T00:00:00.000Z",
      "updatedAt": "2026-06-17T00:00:00.000Z"
    }
  ]
}
```

### 模拟命中

```http
POST /api/admin/automation/simulate
Content-Type: application/json

{ "inboundText": "你好，我想咨询一下价格" }
```

返回是否命中规则、风险级别、是否允许进入确认发送。

### 生成 AI 草稿

```http
POST /api/admin/automation/ai-draft
Content-Type: application/json

{
  "inboundText": "你们这个适合什么样的人？",
  "conversationContext": "可选的最近上下文",
  "extraInstruction": "可选的临时指令"
}
```

### 确认发送命中规则

```http
POST /api/admin/instances/:id/automation/send-rule
Content-Type: application/json

{
  "ruleId": "welcome-001",
  "inboundText": "你好，我想咨询一下价格",
  "conversationName": "张三",
  "confirm": true
}
```

### 确认发送单条文本

```http
POST /api/admin/instances/:id/automation/send-text
Content-Type: application/json

{
  "text": "这是人工确认后的回复",
  "inboundText": "客户刚发来的消息",
  "conversationName": "张三",
  "confirm": true,
  "allowReview": false
}
```

## 和 wecom-ai-assistant 的融合关系

已融合的部分：

- `ReplyPipeline` 思路：先关键词规则，再知识库/AI，再人工处理。
- `RiskClassifier` 思路：阻断高风险词，普通词放行，部分词进入复核。
- `AutomaticReplyPolicy` 思路：已审核规则、冷却时间、每小时上限。
- 审计和人工确认优先的产品边界。

尚未融合的部分：

- 读取微信聊天消息：当前版本还没有可靠 OCR/窗口识别。
- 自动选择联系人/群：当前只负责对当前已聚焦会话发送。
- 朋友圈发布状态机：当前只提供文案草稿和发送基础能力，未实现 UI 点击流程。

## 下一步

1. 增加自动化工作台 UI：规则库、模拟器、AI 草稿、审计记录。
2. 增加实例内感知：截图、OCR、窗口标题、输入框定位。
3. 增加群发队列：白名单、标签、发送间隔、失败重试、暂停/恢复。
4. 增加朋友圈半自动流程：生成内容、准备图片、打开发布页、人工确认。
5. 小范围测试稳定后，再考虑构建自定义镜像并部署到 NAS 的单独测试端口。
