# 自动化融合版

> 本文描述 `andy/automation-lab` 分支新增的自动化实验能力。
> 线上 NAS 当前仍建议保持旧版不变；本分支先用于构建、测试和小范围验证。

## 目标

把 WechatOnCloud 的云微信执行端，与本地 `wecom-ai-assistant` 已验证过的业务逻辑融合：

- AI 回复：规则优先，未命中时生成 AI 草稿；发送前必须人工确认。
- 消息导入：可读取实例剪贴板，或先模拟 Ctrl+C 再读取远程微信里的选中文本。
- 规则沉淀：把当前 AI 草稿一键保存为待审核/已审核关键词规则。
- 企微接入资料：导入企业微信自动化 Mac 版导出的 FAQ、话术、人群分组和运营素材。
- 受众资产：把联系人、客户群、群聊、标签和来源沉淀成长期对象，可一键填入群发队列。
- 群发队列：白名单/群聊名单逐条推进，可自动搜索打开目标会话，再发送下一条。
- 朋友圈半自动：生成/保存/审核朋友圈草稿，可由 Mac Bridge 领取并准备到本机剪贴板或当前输入框，不自动点击发布。
- 风险拦截：投诉、退款、验证码、账号、法律等高风险内容直接阻断。
- 冷却与限流：限制每小时发送量和单会话冷却时间，群发也计入限额。
- 审计记录：记录谁、何时、向哪个实例触发了发送、填入或队列变更动作。

## 安全默认值

这不是一个默认全自动群发器。第一版刻意保守：

- 自动化总开关默认关闭。
- 每条规则默认 `approved=false`。
- 真正发送必须传 `confirm=true`。
- 未审核规则不能发送。
- 风险命中 `block` 时不能发送。
- AI 草稿只生成文本，不自动发送。
- 企微接入资料默认需要审核后才会参与 AI 回复和朋友圈文案。
- 群发队列默认未审核，且每次只发送一个目标。
- 群发自动搜索只使用官方客户端 UI 快捷键，不读取微信数据库、不调用私有协议。
- 朋友圈草稿只复制或填入正文，Bridge 只回写 `prepared/published` 状态，不负责选择图片或点击发布。

## 新增持久化文件

自动化配置与审计记录独立保存：

```text
/data/automation.json
```

Compose 中已通过 `./data-panel:/data` 持久化，因此它会落到宿主的 `data-panel/automation.json`。

## 环境变量

AI 草稿使用 OpenAI-compatible Chat Completions：

```env
AUTOMATION_AI_API_KEY=
AUTOMATION_AI_BASE_URL=https://api.openai.com/v1
AUTOMATION_AI_MODEL=gpt-4o-mini
```

也兼容 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`。

企微 Mac 工具外部推送资料使用 Bridge token，默认关闭：

```env
AUTOMATION_BRIDGE_TOKEN=
```

填入至少 16 位随机 token 后，Mac 工具可以通过 Bridge API 把 FAQ、话术、联系人分组、朋友圈素材和新消息事件推送到面板。token 只放在环境变量或 NAS Compose 配置里，不写入 GitHub。

## 测试端口部署

自动化版建议先和生产面板并行跑，不直接替换 `36080` 上的稳定服务。本分支提供独立 compose：

```bash
AUTOMATION_AI_API_KEY=你的模型Key \
./scripts/deploy-automation-test.sh
```

脚本默认使用：

- `WOC_IMAGE_PREFIX=ghcr.io/andychakwang`
- `WOC_VERSION=andy-automation-usable-r25-2026-07-05`
- `WOC_TEST_HTTP_PORT=36081`
- `PANEL_ALLOWED_HOSTS=nasbot.cloud`

也可以手动指定：

```bash
WOC_IMAGE_PREFIX=ghcr.io/andychakwang \
WOC_VERSION=andy-automation-usable-r25-2026-07-05 \
WOC_TEST_HTTP_PORT=36081 \
PANEL_ALLOWED_HOSTS=nasbot.cloud \
AUTOMATION_AI_API_KEY=你的模型Key \
AUTOMATION_AI_BASE_URL=https://api.openai.com/v1 \
AUTOMATION_AI_MODEL=gpt-4o-mini \
docker compose -f docker-compose.automation-test.yml up -d
```

隔离项：

- 测试面板容器名：`woc-panel-automation-test`
- 测试数据目录：`./data-panel-automation-test`
- 默认测试端口：`36081`
- 生产面板 `woc-panel`、`./data-panel` 和 `36080` 不受影响

飞牛 NAS 的 Docker 面板可以直接导入固定版 compose，见：

```text
fnos/woc-automation-test/docker-compose.yaml
```

详细步骤见 [飞牛 NAS 自动化测试部署](./飞牛NAS自动化测试部署.md)。

首次进入测试面板后：

1. 新建一个测试微信实例并扫码登录。
2. 在「自动化工作台」选择该实例，先跑「实例自检」。
3. 配置 AI Key 后，用「读取选中文本」验证 AI 回复链路。
4. 创建 1-2 个测试群/联系人队列，先用测试内容跑「发下一条」。
5. 朋友圈先用「复制」模式验证，再尝试「填入」模式。

自动化工作台顶部有运营总览：总开关、已审核资料、AI 回复待办、群发待发送目标、朋友圈待准备草稿、Mac Bridge 在线 worker 和出箱待办会统一显示。这个总览来自 `/api/admin/automation/overview`，只读统计当前 JSON store，不会触发发送、领取或发布。

## API

所有自动化管理接口都要求管理员登录。

### 实例自动化自检

```http
POST /api/admin/instances/:id/automation/self-test
```

检查当前实例的自动化基础环境：`DISPLAY`、`xclip`、`xdotool`、活动窗口和剪贴板回环。建议在第一次跑 AI 回复、群发队列或朋友圈草稿前先点管理页里的「实例自检」。

### 运营总览

```http
GET /api/admin/automation/overview
```

返回自动化工作台顶部的只读汇总：资料/规则数量、Bridge 消息待办、Mac worker 在线数、群发队列状态、朋友圈草稿状态和最近审计事件。它只读取当前 store，不会领取 Bridge 任务，也不会执行发送。

### 读取配置

```http
GET /api/admin/automation/config
```

### 企微接入资料

导入企业微信自动化 Mac 版导出的资料：

```http
POST /api/admin/automation/knowledge/import
Content-Type: application/json

{
  "source": "wecom-mac",
  "category": "faq",
  "approveImported": false,
  "mode": "upsert",
  "items": [
    {
      "title": "价格咨询边界",
      "category": "policy",
      "tags": ["价格", "报价"],
      "triggers": ["多少钱", "费用", "报价"],
      "content": "价格问题先确认客户场景，不在 AI 回复里编造报价。",
      "targetNames": []
    },
    {
      "title": "测试群发白名单",
      "category": "contact-group",
      "targetNames": ["测试客户群", "张三"]
    }
  ]
}
```

也可以把 JSON、Markdown 或纯文本块放在 `rawText` 字段里，后端会按段落拆成资料。`mode=upsert` 会按 `source + title` 更新同名资料，避免重复导入。

更新审核/启用状态：

```http
PATCH /api/admin/automation/knowledge/:itemId
Content-Type: application/json

{ "approved": true, "enabled": true }
```

删除资料：

```http
DELETE /api/admin/automation/knowledge/:itemId
```

只有 `enabled=true` 且 `approved=true` 的资料会被送进 AI prompt；未审核资料只保存在工作台，不影响实际回复。

### 受众资产

导入企业微信自动化 Mac 版导出的联系人、客户群或群聊：

```http
POST /api/admin/automation/audience/import
Content-Type: application/json

{
  "source": "wecom-mac",
  "type": "group",
  "approveImported": false,
  "mode": "upsert",
  "contacts": [
    {
      "name": "测试客户群",
      "aliases": ["测试群"],
      "tags": ["白名单", "活动提醒"],
      "note": "只用于自动化 smoke 和小范围验证"
    }
  ]
}
```

也可以把一行一个联系人/群聊名放在 `rawText` 字段里。`mode=upsert` 会按 `source + name + type` 更新同名受众，避免重复导入。受众本身不会触发发送，只是长期资产；创建群发队列时仍会生成独立的受控队列，并继续走审核、限流和 Bridge 领取流程。

读取、更新、删除：

```http
GET /api/admin/automation/audience?limit=200&query=&tag=
PATCH /api/admin/automation/audience/:contactId
DELETE /api/admin/automation/audience/:contactId
```

### Mac Bridge 推送

测试面板设置 `AUTOMATION_BRIDGE_TOKEN` 后，企业微信自动化 Mac 版可以不登录 Web 管理页，直接推送资料：

```http
POST /api/automation/bridge/wecom/import
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
Content-Type: application/json

{
  "source": "wecom-mac",
  "category": "faq",
  "mode": "upsert",
  "approveImported": false,
  "items": [
    {
      "title": "价格咨询边界",
      "tags": ["价格"],
      "triggers": ["多少钱", "报价"],
      "content": "价格问题先确认客户场景，不在 AI 回复里编造报价。"
    }
  ]
}
```

也可以用 `X-Automation-Token: <token>` 请求头。Bridge 只负责导入资料，不执行发送、群发或朋友圈发布动作；导入后的资料仍需要管理员审核后才会影响 AI 回复。

Mac 工具也可以同步联系人、客户群或群聊到受众资产池：

```http
POST /api/automation/bridge/wecom/audience
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
Content-Type: application/json

{
  "source": "wecom-mac",
  "type": "group",
  "mode": "upsert",
  "contacts": [
    { "name": "测试客户群", "tags": ["白名单"] }
  ]
}
```

Mac 工具也可以把捕捉到的新消息推送到收件箱：

```http
POST /api/automation/bridge/wecom/events
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
Content-Type: application/json

{
  "source": "wecom-mac",
  "events": [
    {
      "externalId": "msg-20260705-001",
      "conversationName": "客户A",
      "senderName": "客户A",
      "inboundText": "你们这个服务适合什么样的人？",
      "conversationContext": "最近几轮对话，可选",
      "receivedAt": "2026-07-05T03:40:00.000Z"
    }
  ]
}
```

带 `externalId` 时按 `source + externalId` 去重更新；没有 `externalId` 时按新事件插入。Web 管理页会在「企微消息收件箱」里显示未归档事件，点击「生成回复」只会填入 AI 回复工作台并标记为 `planned`，不会自动发送。

Mac 工具可以定时上报心跳，让 Web 管理页显示本机 worker 是否在线、最近运行模式、待处理回复数、待群发任务数和待朋友圈任务数：

```http
POST /api/automation/bridge/wecom/heartbeat
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
Content-Type: application/json

{
  "source": "wecom-mac",
  "workerId": "mac-mini-01",
  "mode": "prepare",
  "host": "Mac-mini",
  "pid": 12345,
  "version": "your-client-version"
}
```

心跳不会领取或发送任何内容；它只刷新 Bridge worker 状态，并返回当前待交付回复数量、待群发任务数量和待朋友圈任务数量。

Mac 工具每轮执行结束后可以上报运行报告，让 Web 管理页看到最近 dry-run/prepare/send 的处理量、失败量、耗时和错误摘要：

```http
POST /api/automation/bridge/wecom/run-report
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
Content-Type: application/json

{
  "source": "wecom-mac",
  "workerId": "mac-mini-01",
  "mode": "dry-run",
  "target": "all",
  "status": "completed",
  "startedAt": "2026-07-05T03:40:00.000Z",
  "finishedAt": "2026-07-05T03:40:03.000Z",
  "durationMs": 3000,
  "handledReplies": 2,
  "handledMassTasks": 1,
  "handledMomentTasks": 1,
  "failedReplies": 0,
  "failedMassTasks": 0,
  "failedMomentTasks": 0,
  "summary": "dry-run total=4"
}
```

管理员可用 `GET /api/admin/automation/bridge-runs?limit=50` 查看最近运行报告；报告会保留最近 300 条，用于 SaaS 运维看板和多 worker 排障。

管理员在收件箱里保存并批准回复草稿后，Mac 工具可以拉取待执行回复：

```http
GET /api/automation/bridge/wecom/replies?limit=50
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
```

返回的是已批准、未交付、未归档的事件，包含 `replyDraft`、会话名和原始消息。Mac 工具执行前仍应在本机界面做一次人工确认或停在发送前确认。

Mac 工具执行前可以先领取，避免多台 Mac 同时处理同一条：

```http
PATCH /api/automation/bridge/wecom/replies/:eventId
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
Content-Type: application/json

{
  "deliveryStatus": "claimed",
  "workerId": "mac-mini-01",
  "claimTtlSeconds": 300
}
```

领取后的回复默认不会再出现在 `GET /replies` 待处理列表里；如果 Mac 工具没有回写成功/失败，领取状态默认 300 秒后过期，届时该回复会重新出现在待处理列表中。Mac 工具处理失败时，可以标记失败并记录原因，方便 Web 面板查看和下次重试：

```http
PATCH /api/automation/bridge/wecom/replies/:eventId
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
Content-Type: application/json

{
  "deliveryStatus": "failed",
  "workerId": "mac-mini-01",
  "error": "企业微信窗口未找到"
}
```

如果只是本机取消处理、窗口没准备好，想立即放回待处理列表，可以释放领取：

```http
PATCH /api/automation/bridge/wecom/replies/:eventId
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
Content-Type: application/json

{
  "deliveryStatus": "released",
  "workerId": "mac-mini-01"
}
```

Mac 工具处理成功后，可以标记已交付：

```http
PATCH /api/automation/bridge/wecom/replies/:eventId
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
Content-Type: application/json

{
  "deliveryStatus": "delivered",
  "workerId": "mac-mini-01"
}
```

为了兼容早期客户端，空 JSON `{}` 仍等价于 `delivered`。

这只会记录 `replyDeliveredAt`，不会由云端直接发送消息。

管理员审核并启动群发队列后，Mac 工具也可以拉取受控群发任务：

```http
GET /api/automation/bridge/wecom/mass-tasks?limit=50
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
```

返回的是已开启自动化总开关、已开启群发开关、已审核且状态为 `queued/running` 的队列任务。每个队列同一时间只暴露第一个 `pending` 目标，保证顺序推进；被有效领取的目标不会再出现在待处理列表中。

```http
PATCH /api/automation/bridge/wecom/mass-tasks/:taskId
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
Content-Type: application/json

{
  "deliveryStatus": "claimed",
  "workerId": "mac-mini-01",
  "claimTtlSeconds": 300
}
```

`deliveryStatus` 可取：

- `claimed`：领取任务，默认 300 秒后超时释放。
- `released`：窗口未准备好时释放领取，立即回到待处理列表。
- `failed`：标记当前目标失败，并暂停队列，Web 管理页可重置或跳过。
- `sent` / `delivered`：标记当前目标已发送，队列继续推进或完成。

这只会更新队列状态；真正打开企业微信、搜索目标、粘贴或发送消息仍发生在 Mac 本机。

管理员审核朋友圈草稿并置为 `ready` 后，Mac 工具可以拉取半自动朋友圈任务：

```http
GET /api/automation/bridge/wecom/moment-tasks?limit=50
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
```

返回的是已开启自动化总开关、已开启朋友圈开关、已审核且状态为 `ready` 的草稿。被有效领取的草稿不会再出现在待处理列表中。

```http
PATCH /api/automation/bridge/wecom/moment-tasks/:taskId
Authorization: Bearer <AUTOMATION_BRIDGE_TOKEN>
Content-Type: application/json

{
  "deliveryStatus": "claimed",
  "workerId": "mac-mini-01",
  "claimTtlSeconds": 300
}
```

`deliveryStatus` 可取：

- `claimed`：领取草稿，默认 300 秒后超时释放。
- `released`：窗口未准备好时释放领取，立即回到待处理列表。
- `failed`：标记准备失败，草稿退回未审核 `draft`，避免反复重试。
- `prepared`：Mac 端已把文案准备到剪贴板或当前输入框，Web 状态变为 `prepared`。
- `published`：人工确认已经发布后回写状态；Bridge 本身不会点击发布。

这只会更新草稿状态；真正打开企业微信、进入朋友圈、粘贴正文和发布确认仍发生在 Mac 本机。

如果 Mac 项目已经有本地发送脚本，可以用 `run-approved` 串起来：

```bash
node scripts/wecom-bridge-client.mjs run-approved \
  --handler './send-to-wecom.sh' \
  --claim \
  --mark-delivered \
  --report-failure
```

`run-approved` 会把单条回复 JSON 写入 handler 的 stdin，并设置 `WECOM_BRIDGE_REPLY_ID`、`WECOM_BRIDGE_CONVERSATION_NAME`、`WECOM_BRIDGE_SENDER_NAME`、`WECOM_BRIDGE_REPLY_DRAFT` 环境变量。只有 handler 退出码为 `0`，并且显式传了 `--mark-delivered`，客户端才会回写已交付。这样 Mac 侧仍可以停在发送前确认或做本机风控。

`--claim-ttl-seconds` 可控制领取超时时间，默认 300 秒。超时后回复会再次被 `pull-replies`/`run-approved` 拉到；未超时前，其他 worker 不能抢占同一条回复。

群发队列也可以用 `run-mass` 串接本机 handler：

```bash
node scripts/wecom-bridge-client.mjs run-mass \
  --handler './scripts/wecom-mac-mass-handler.sh' \
  --claim \
  --mark-sent \
  --report-failure
```

`run-mass` 会把单条群发任务 JSON 写入 handler 的 stdin，并设置 `WECOM_BRIDGE_MASS_TASK_ID`、`WECOM_BRIDGE_RECIPIENT_NAME`、`WECOM_BRIDGE_MASS_MESSAGE` 等环境变量。只有 handler 退出码为 `0`，并且显式传了 `--mark-sent`，客户端才会回写已发送。

朋友圈半自动也可以用 `run-moments` 串接本机 handler：

```bash

  --handler './scripts/wecom-mac-moment-handler.sh' \
  --claim \
  --mark-prepared \

```

`run-moments` 会把单条朋友圈任务 JSON 写入 handler 的 stdin，并设置 `WECOM_BRIDGE_MOMENT_TASK_ID`、`WECOM_BRIDGE_MOMENT_TEXT`、`WECOM_BRIDGE_MOMENT_MATERIALS` 等环境变量。默认建议只传 `--mark-prepared`；人工确认已经发布后，再单独执行 `mark-moment-published <taskId>` 回写发布状态。

仓库也提供了一个 AppleScript 包装的企业微信 Mac handler 模板：

```bash
# 只解析 Bridge 回复，不碰企业微信窗口
WECOM_HANDLER_MODE=dry-run \
  scripts/wecom-mac-reply-handler.sh < doc/examples/wecom-bridge-reply.sample.json

# 默认 prepare：打开企业微信、搜索会话、把回复粘贴到输入框，不按回车
WECOM_HANDLER_MODE=prepare \
WECOM_APP_NAME='企业微信' \
WECOM_SEARCH_SHORTCUT='command+k' \
  node scripts/wecom-bridge-client.mjs run-approved \
    --handler './scripts/wecom-mac-reply-handler.sh' \
    --claim \
    --report-failure

# 真正发送必须双重确认：mode=send 且 WECOM_ALLOW_SEND=1
WECOM_HANDLER_MODE=send \
WECOM_ALLOW_SEND=1 \
  node scripts/wecom-bridge-client.mjs run-approved \
    --handler './scripts/wecom-mac-reply-handler.sh' \
    --claim \
    --mark-delivered \
    --report-failure
```

这个 handler 需要 macOS「系统设置 → 隐私与安全性 → 辅助功能」允许终端或运行器控制电脑。`WECOM_SEARCH_SHORTCUT=none` 时不会搜索会话，只会把回复粘贴到当前打开的会话输入框，适合先手动定位窗口再联调。

### Mac 定时运行

如果要让 Mac 端定时检查云端批准回复、群发任务和朋友圈任务，可以用 runner：

Web 管理页的「自动化工作台 → 企微接入资料 → Mac Runner 接入」会根据当前访问域名生成 `~/.config/wechat-on-cloud/wecom-bridge.env` 模板和常用运行命令。模板只包含 token 占位符，不会把 NAS 容器里的真实 `AUTOMATION_BRIDGE_TOKEN` 回显到浏览器；真实 token 仍从飞牛 NAS 的 Docker 环境变量里复制。

```bash
export WOC_PANEL_URL='http://nasbot.cloud:36081'
export AUTOMATION_BRIDGE_TOKEN='至少16位随机字符串'

# 安全默认：只列出待处理回复，不领取、不碰窗口
WECOM_RUNNER_MODE=dry-run scripts/wecom-bridge-runner.sh run-once

# 群发队列 dry-run：只列出待处理群发任务
WECOM_RUNNER_MODE=dry-run \
WECOM_RUNNER_TARGET=mass \
scripts/wecom-bridge-runner.sh run-once

# 朋友圈 dry-run：只列出待处理朋友圈任务
WECOM_RUNNER_MODE=dry-run \
WECOM_RUNNER_TARGET=moments \
scripts/wecom-bridge-runner.sh run-once

# 全队列 dry-run：一次汇总回复、群发和朋友圈三类待办
WECOM_RUNNER_MODE=dry-run \
WECOM_RUNNER_TARGET=all \
scripts/wecom-bridge-runner.sh run-once

# prepare：领取回复并粘贴到企业微信输入框，不自动发送
WECOM_RUNNER_MODE=prepare \
WECOM_BRIDGE_WORKER_ID='mac-mini-01' \
WECOM_CLAIM_TTL_SECONDS=300 \
scripts/wecom-bridge-runner.sh run-once

# prepare 群发：领取群发任务并粘贴到目标会话，不自动发送
WECOM_RUNNER_MODE=prepare \
WECOM_RUNNER_TARGET=mass \
WECOM_BRIDGE_WORKER_ID='mac-mini-01' \
WECOM_CLAIM_TTL_SECONDS=300 \
scripts/wecom-bridge-runner.sh run-once

# prepare 朋友圈：领取草稿并复制到剪贴板，或 current-input 模式粘贴到发布框
WECOM_RUNNER_MODE=prepare \
WECOM_RUNNER_TARGET=moments \
WECOM_MOMENT_PASTE_MODE=clipboard-only \
WECOM_BRIDGE_WORKER_ID='mac-mini-01' \
WECOM_CLAIM_TTL_SECONDS=300 \
scripts/wecom-bridge-runner.sh run-once

# prepare 全队列：按回复、群发、朋友圈顺序处理；朋友圈只准备到剪贴板或发布框
WECOM_RUNNER_MODE=prepare \
WECOM_RUNNER_TARGET=all \
WECOM_MOMENT_PASTE_MODE=clipboard-only \
WECOM_BRIDGE_WORKER_ID='mac-mini-01' \
WECOM_CLAIM_TTL_SECONDS=300 \
scripts/wecom-bridge-runner.sh run-once

# send：领取、粘贴、按回车发送，并回写 delivered
WECOM_RUNNER_MODE=send \
WECOM_ALLOW_SEND=1 \
WECOM_BRIDGE_WORKER_ID='mac-mini-01' \
WECOM_CLAIM_TTL_SECONDS=300 \
scripts/wecom-bridge-runner.sh run-once

# send 全队列：回复和群发会发送；朋友圈仍跳过发布，只保留人工确认流程
WECOM_RUNNER_MODE=send \
WECOM_RUNNER_TARGET=all \
WECOM_ALLOW_SEND=1 \
WECOM_BRIDGE_WORKER_ID='mac-mini-01' \
WECOM_CLAIM_TTL_SECONDS=300 \
scripts/wecom-bridge-runner.sh run-once
```

runner 每次运行都会先上报一次 `heartbeat`，即使没有待处理回复、群发任务或朋友圈任务，Web 管理页也能看到 Mac 端最近是否在线；runner 调用 `run-approved`、`run-mass`、`run-moments` 时会带 `--report-run` 自动回写本轮运行报告。prepare 模式会 `claim` 当前任务，因此不会重复出现在待处理列表里；人工确认发送后，应再执行 `mark-delivered <eventId>` 或 `mark-mass-sent <taskId>`；人工确认朋友圈已经发布后，执行 `mark-moment-published <taskId>`。`WECOM_RUNNER_TARGET=all` 会按 replies → mass → moments 顺序运行；真实无人值守发送只建议在小号/测试群充分验证后启用 `send`；朋友圈 target 当前不支持 runner 的 `send` 模式，all+send 也会跳过朋友圈发布。

也可以安装 macOS 用户级 LaunchAgent 定时运行：

```bash
WOC_PANEL_URL='http://nasbot.cloud:36081' \
AUTOMATION_BRIDGE_TOKEN='至少16位随机字符串' \
WECOM_RUNNER_MODE='dry-run' \
WECOM_RUNNER_TARGET='all' \
WECOM_BRIDGE_INTERVAL_SEC=60 \
scripts/install-wecom-bridge-launchagent.sh
```

安装脚本会生成：

- 配置文件：`~/.config/wechat-on-cloud/wecom-bridge.env`，权限 `600`，包含 Bridge token。
- LaunchAgent：`~/Library/LaunchAgents/com.wechatoncloud.wecom-bridge.plist`。
- 日志：`~/Library/Logs/com.wechatoncloud.wecom-bridge.log` 和 `.err.log`。

先用 `--dry-run` 查看将写入的配置和 plist，不会落盘：

```bash

```

### 群发队列

创建队列：

```http
POST /api/admin/automation/mass-jobs
Content-Type: application/json

{
  "title": "6 月活动提醒",
  "message": "这是一条经过确认的群发内容",
  "recipients": ["客户群 A", "张三"],
  "options": {
    "perSendDelaySeconds": 10,
    "requireOperatorConfirmRecipient": true,
    "openConversationBeforeSend": true,
    "searchShortcut": "ctrl+f",
    "searchResultDelaySeconds": 2,
    "postOpenDelaySeconds": 1
  }
}
```

审核/暂停/取消队列：

```http
PATCH /api/admin/automation/mass-jobs/:jobId
Content-Type: application/json

{ "approved": true, "status": "queued" }
```

发送下一条：

```http
POST /api/admin/instances/:id/automation/mass-jobs/:jobId/send-next
Content-Type: application/json

{
  "confirm": true,
  "operatorConfirmedRecipient": true,
  "openConversationBeforeSend": true
}
```

注意：

- `openConversationBeforeSend=true` 时，面板会尝试用搜索快捷键打开目标会话，再粘贴发送内容。
- 如果某个微信版本快捷键不一致，可把队列改成 `openConversationBeforeSend=false`，回到“人工打开当前会话后发送”的受控模式。
- 无论哪种模式，每次发送仍要求 `confirm=true` 和 `operatorConfirmedRecipient=true`。
- 如果发送失败，队列会自动暂停，当前目标标记为 `failed`，管理页可把目标重置为 `pending` 后重试，也可以跳过继续跑后续目标。

更新单个队列目标状态：

```http
PATCH /api/admin/automation/mass-jobs/:jobId/items/:itemId
Content-Type: application/json

{ "status": "skipped", "reason": "本次不发送" }
```

## 和 wecom-ai-assistant 的融合关系

已融合的部分：

- `ReplyPipeline` 思路：先关键词规则，再知识库/AI，再人工处理。
- 企微自动化 Mac 版资料接入：FAQ、话术、边界、人群分组和朋友圈素材可以导入为结构化资料。
- 受众资产池：联系人、客户群、群聊、标签和来源可长期沉淀，并一键填入群发队列。
- Mac Bridge：企微 Mac 工具可用 token 把资料推送到云端面板，不必手工复制粘贴。
- Bridge 消息收件箱：企微 Mac 工具可把新消息推到面板，管理员一键带入 AI 回复流程。
- Bridge 回复出箱：管理员批准后的回复草稿可供 Mac 工具拉取执行，云端仍不直接发送。
- Bridge 朋友圈出箱：管理员审核后的朋友圈草稿可供 Mac 工具领取并准备，人工发布后回写状态。
- AI 回复和朋友圈文案会自动引用已审核接入资料；人群分组可在管理页填入群发目标。
- `RiskClassifier` 思路：阻断高风险词，普通词放行，部分词进入复核。
- `AutomaticReplyPolicy` 思路：已审核规则、冷却时间、每小时上限。
- 审计和人工确认优先的产品边界。
- 管理页工作台：AI 回复、群发队列、朋友圈草稿和最近审计记录集中在一个入口。
- Docker 执行器：会话搜索打开、实例剪贴板读写、自动化环境自检。
- 群发队列恢复能力：失败自动暂停，目标可跳过、重置或标记失败。

尚未融合的部分：

- Mac 版工具已经可以通过 Bridge 领取 AI 回复、群发任务和朋友圈任务，并由本机 handler 搜索会话、准备文案、粘贴或发送；但窗口状态/OCR 校验还没有直连。

- 朋友圈发布状态机：当前 Bridge 已支持半自动领取、准备和状态回写，未实现自动打开入口、选图和点击发布的 RPA 流程。
