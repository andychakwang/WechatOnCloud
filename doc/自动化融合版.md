# 自动化融合版

> 本文描述 `andy/automation-lab` 分支新增的自动化实验能力。
> 线上 NAS 当前仍建议保持旧版不变；本分支先用于构建、测试和小范围验证。

## 目标

把 WechatOnCloud 的云微信执行端，与本地 `wecom-ai-assistant` 已验证过的业务逻辑融合：

- AI 回复：规则优先，未命中时生成 AI 草稿；发送前必须人工确认。
- 消息导入：可读取实例剪贴板，或先模拟 Ctrl+C 再读取远程微信里的选中文本。
- 规则沉淀：把当前 AI 草稿一键保存为待审核/已审核关键词规则。
- 群发队列：白名单/群聊名单逐条推进，可自动搜索打开目标会话，再发送下一条。
- 朋友圈半自动：生成/保存朋友圈草稿，可复制到实例剪贴板或填入当前发布框，不自动点击发布。
- 风险拦截：投诉、退款、验证码、账号、法律等高风险内容直接阻断。
- 冷却与限流：限制每小时发送量和单会话冷却时间，群发也计入限额。
- 审计记录：记录谁、何时、向哪个实例触发了发送、填入或队列变更动作。

## 安全默认值

这不是一个默认全自动群发器。第一版刻意保守：

- 自动化总开关默认关闭。
- 每条规则默认 `approved=false`。
- 真正发送必须传 `confirm=true`。
- 未审核规则不能发送。
- 风险命中 `block` 时不能发送。
- AI 草稿只生成文本，不自动发送。
- 群发队列默认未审核，且每次只发送一个目标。
- 群发自动搜索只使用官方客户端 UI 快捷键，不读取微信数据库、不调用私有协议。
- 朋友圈草稿只复制或填入正文，不负责选择图片或点击发布。

## 新增持久化文件

自动化配置与审计记录独立保存：

```text
/data/automation.json
```

Compose 中已通过 `./data-panel:/data` 持久化，因此它会落到宿主的 `data-panel/automation.json`。

## 环境变量

AI 草稿使用 OpenAI-compatible Chat Completions：

```env
AUTOMATION_AI_API_KEY=
AUTOMATION_AI_BASE_URL=https://api.openai.com/v1
AUTOMATION_AI_MODEL=gpt-4o-mini
```

也兼容 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`。

## API

所有自动化管理接口都要求管理员登录。

### 读取配置

```http
GET /api/admin/automation/config
```

### 保存配置

```http
PUT /api/admin/automation/config
Content-Type: application/json

{
  "settings": {
    "enabled": true,
    "aiDraftEnabled": true,
    "automaticRuleRepliesEnabled": true,
    "massSendEnabled": true,
    "momentsEnabled": true,
    "maximumAutomaticSendsPerHour": 20,
    "perConversationCooldownMinutes": 10,
    "requireConfirmForSend": true
  },
  "persona": "你的账号人设和回复风格",
  "knowledgeNotes": "业务资料、报价边界、禁答规则",
  "rules": [
    {
      "id": "welcome-001",
      "name": "咨询欢迎语",
      "enabled": true,
      "approved": true,
      "priority": 10,
      "triggers": ["怎么了解", "咨询", "价格"],
      "responseSteps": [
        { "type": "text", "text": "你好，我先把资料发你，你可以先看一下。", "sendEnter": true },
        { "type": "wait", "seconds": 2 },
        { "type": "text", "text": "如果你方便，也可以直接说下你的需求，我帮你匹配。", "sendEnter": true }
      ],
      "createdAt": "2026-06-17T00:00:00.000Z",
      "updatedAt": "2026-06-17T00:00:00.000Z"
    }

```

### 模拟命中

```http
POST /api/admin/automation/simulate
Content-Type: application/json

{ "inboundText": "你好，我想咨询一下价格" }
```

返回是否命中规则、风险级别、是否允许进入确认发送。

### 生成回复计划

```http
POST /api/admin/automation/reply-plan
Content-Type: application/json

{
  "inboundText": "你们这个适合什么样的人？",
  "conversationContext": "可选的最近上下文",
  "extraInstruction": "可选的临时指令"
}
```

返回 `keyword-rule`、`ai-draft`、`manual-review` 或 `blocked`，用于管理页「AI 回复」工作台。

### 读取实例剪贴板

```http
POST /api/admin/instances/:id/automation/read-clipboard
Content-Type: application/json

{ "copySelection": true }
```

- `copySelection=true`：先在实例里模拟 `Ctrl+C`，再读取剪贴板，适合远程微信里已经选中一段客户消息的场景。
- `copySelection=false`：直接读取实例当前剪贴板。
- 返回文本只进入工作台输入框，不会自动发送。

### 生成 AI 草稿

```http
POST /api/admin/automation/ai-draft
Content-Type: application/json

{
  "inboundText": "你们这个适合什么样的人？",
  "conversationContext": "可选的最近上下文",
  "extraInstruction": "可选的临时指令"
}
```

### 确认发送命中规则

```http
POST /api/admin/instances/:id/automation/send-rule
Content-Type: application/json

{
  "ruleId": "welcome-001",
  "inboundText": "你好，我想咨询一下价格",
  "conversationName": "张三",
  "confirm": true
}
```

### 确认发送单条文本

```http
POST /api/admin/instances/:id/automation/send-text
Content-Type: application/json

{
  "text": "这是人工确认后的回复",
  "inboundText": "客户刚发来的消息",
  "conversationName": "张三",
  "confirm": true,
  "allowReview": false
}
```

### 群发队列

创建队列：

```http
POST /api/admin/automation/mass-jobs
Content-Type: application/json

{
  "title": "6 月活动提醒",
  "message": "这是一条经过确认的群发内容",
  "recipients": ["客户群 A", "张三"],
  "options": {
    "perSendDelaySeconds": 10,
    "requireOperatorConfirmRecipient": true,
    "openConversationBeforeSend": true,
    "searchShortcut": "ctrl+f",
    "searchResultDelaySeconds": 2,
    "postOpenDelaySeconds": 1
  }
}
```

审核/暂停/取消队列：

```http
PATCH /api/admin/automation/mass-jobs/:jobId
Content-Type: application/json

{ "approved": true, "status": "queued" }
```

发送下一条：

```http
POST /api/admin/instances/:id/automation/mass-jobs/:jobId/send-next
Content-Type: application/json

{
  "confirm": true,
  "operatorConfirmedRecipient": true,
  "openConversationBeforeSend": true
}
```

注意：

- `openConversationBeforeSend=true` 时，面板会尝试用搜索快捷键打开目标会话，再粘贴发送内容。
- 如果某个微信版本快捷键不一致，可把队列改成 `openConversationBeforeSend=false`，回到“人工打开当前会话后发送”的受控模式。
- 无论哪种模式，每次发送仍要求 `confirm=true` 和 `operatorConfirmedRecipient=true`。

### 朋友圈草稿

AI 生成文案：

```http
POST /api/admin/automation/moment-drafts/ai-draft
Content-Type: application/json

{
  "topic": "本周 AI 自动化实践复盘",
  "audience": "私域客户和学员",
  "tone": "自然、克制、有个人感"
}
```

保存草稿：

```http
POST /api/admin/automation/moment-drafts
Content-Type: application/json

{
  "title": "AI 自动化复盘",
  "text": "朋友圈正文",
  "imageNotes": "配 3 张操作截图",
  "materials": ["screenshot-1.png", "screenshot-2.png"]
}
```

填入当前朋友圈发布框：

```http
POST /api/admin/instances/:id/automation/moment-drafts/:draftId/prepare
Content-Type: application/json

{ "confirm": true, "mode": "copy-to-clipboard" }
```

`mode` 可选：

- `copy-to-clipboard`：只复制到实例剪贴板，用户自己在朋友圈发布框里粘贴。
- `fill-current-input`：直接粘贴到当前焦点输入框，适合已经打开朋友圈发布框并定位好光标的场景。

图片选择、发布前检查和点击发布仍由人工完成。

## 和 wecom-ai-assistant 的融合关系

已融合的部分：

- `ReplyPipeline` 思路：先关键词规则，再知识库/AI，再人工处理。
- `RiskClassifier` 思路：阻断高风险词，普通词放行，部分词进入复核。
- `AutomaticReplyPolicy` 思路：已审核规则、冷却时间、每小时上限。
- 审计和人工确认优先的产品边界。
- 管理页工作台：AI 回复、群发队列、朋友圈草稿和最近审计记录集中在一个入口。
- Docker 执行器：新增会话搜索打开、实例剪贴板读写两个 RPA 原语。

尚未融合的部分：

- 读取微信聊天消息：当前版本还没有可靠 OCR/窗口识别。
- 联系人/群匹配校验：当前可自动搜索打开，但还没有 OCR 反查“是否确实打开了目标会话”。
- 朋友圈发布状态机：当前只复制/填入文案，未实现打开入口、选图和点击发布的 RPA 流程。

## 下一步

1. 增加实例内感知：截图、OCR、窗口标题、输入框定位。
2. 增加联系人/群聊搜索执行器：从受控队列升级为可验证的 RPA 队列。
3. 增加朋友圈发布状态机：打开朋友圈入口、进入发布框、选图、填文案、停在发布确认前。
4. 增加失败重试、暂停/恢复、队列导入导出。
5. 小范围测试稳定后，再考虑构建自定义镜像并部署到 NAS 的单独测试端口。
